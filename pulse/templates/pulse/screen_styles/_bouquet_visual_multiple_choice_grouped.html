{% comment %} Bouquet's multiple_choice_grouped diagram type ("Ribbon Rows"): one horizontal stem per group, every option's blossom strung along it left-to-right by rank (highest pct first -- NOT centre-out like the single-group fan, _bouquet_visual_multiple_choice.html) -- geometry computed by views._bouquet_geometry_multiple_choice_grouped. Bloom size and fill-opacity both scale with the real pct, normalized against the single highest pct anywhere in the whole breakdown (see that function's docstring for the exact formula). Only the top-scoring bloom(s) in each row (a genuine tie shows more than one) get their "Label pct%" line above the stem, in the larger of the two sizes; everyone else gets the same "Label pct%" shape below the stem, smaller -- the same "only the winner gets the prominent label" trade-off the RibbonRows mockup made, so a 5-option x 5-group grid still fits on one screen without every one of 25 labels competing for space. Each label's `width` is `row.slot_width` (that row's own real per-option slot, see the geometry function's docstring), not its natural text width -- long option text truncates with an ellipsis (CSS `text-overflow: ellipsis` in screen_styles.css) rather than overflowing into a neighboring slot's label. Every coordinate is page-absolute within the 1920x1080 stage (same convention as the other grouped/_multiple_choice partials), so `.mcg-visual` sits at inset:0. {% endcomment %}
