{% comment %} Bouquet's number_grouped diagram type ("Ribbon Rows"): one row per group, each just a flower + the group's own single aggregated value + the aggregation tag ("MEDEL", "MEDIAN", ...) -- no shared axis or scale drawn behind the rows, same reasoning as the single-group _bouquet_visual_number.html (views._bouquet_geometry_number_grouped's docstring). The tag text is identical on every row (one BigScreenState.aggregation setting governs the whole reveal), but is still rendered per row rather than once for the whole diagram -- same "caption sits right next to its own number" layout the Generalization mockup used, so a row reads correctly in isolation without the eye having to hunt for a shared label elsewhere. The flower itself is NOT uniformly sized across rows (added 2026-09-15) -- `row.flower_size` is this row's own value scaled relative to the min/max actually present in this view (see _bouquet_geometry_number_grouped's docstring for exactly what that does and doesn't claim). `.ng-bloom` is centred on its own `left`/`top` via `transform: translate(-50%,-50%)` in CSS regardless of its `width`/`height`, so a bigger or smaller flower never needs its own anchor math here -- only the geometry function's per-row `flower_size` differs, the template stays generic. Every coordinate is page-absolute within the 1920x1080 stage (same convention as the other grouped partials), so `.ng-visual` sits at inset:0. {% endcomment %}
